B. A nickname for each Pi
4. The SSH configuration file
  • A small text file where I describe each machine once. Then ssh, scp and other tools accept the nickname.
# 1 create the folder and an empty file named exactly "config" (no .txt), open it
New-Item -ItemType Directory -Force $env:USERPROFILE\.ssh | Out-Null
New-Item -ItemType File -Force $env:USERPROFILE\.ssh\config | Out-Null
notepad $env:USERPROFILE\.ssh\config
2 type one block per Pi (indent with spaces) - file: C:\Users\me\.ssh\config
Host lab
    HostName raspi-lab.local
    User piuser

Host home
    HostName raspi-home.local
    User piuser

Host *
    ServerAliveInterval 60
# 3 test: only the nickname
ssh lab
Host labstarts a block; lab is the nickname
HostNamethe real destination: a .local name or an IP address (IP if .local is unreliable)
Userwho I log in as; no need for piuser@
Host * / ServerAliveInterval 60for all hosts: a signal every 60 s keeps idle connections open
Mac / Linux: ~/.ssh/config, same contents (mkdir -p ~/.ssh; nano ~/.ssh/config).

B. SSH keys
5. Log in without a password
  • A password can be guessed, mistyped or stolen. A key pair is stronger: a private key (secret, stays on the laptop) and a public key (harmless to share) placed on the Pi.
# 1 create the pair on the laptop (Enter = default file; passphrase optional but protective)
ssh-keygen -t ed25519 -C "office-laptop"
# creates id_ed25519 (private, secret) and id_ed25519.pub (public) in .ssh
# 2 send the PUBLIC key to the Pi (asks the password one last time)
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh lab "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
# Mac / Linux: ssh-copy-id lab
# 3 test
ssh lab
Rules: never copy the private key anywhere. One key per laptop: with two laptops, create a key on each and add both public keys to each Pi. A re-written card loses its authorized_keys: repeat step 2. Keep password login on until the key works.

C. Moving files with scp
8. scp: copy over SSH
  • Same encrypted channel as SSH: nothing extra on the Pi. Pattern: scp SOURCE DESTINATION. name:path = on the Pi; a plain path = on this computer.
Practice (10 min)
# 1 a test file on the laptop (in a writable folder)
"Hello from my laptop" | Out-File test.txt -Encoding ascii
# 2 send it (the colon is required; ~/ = my home folder on the Pi)
scp test.txt lab:~/
# 3 check on the Pi
ssh lab
ls -l ; cat test.txt ; cp test.txt test_2.txt ; exit
# 4 fetch a file (the dot = the current folder here)
scp lab:test_2.txt .
Windows paths: open PowerShell in the folder that holds the file and use short names. A path like C:\Users\me\f.txt contains a colon that can confuse scp about what is local.

C. Sync with git; which tool?
11. Several computers in sync with git
  • With two laptops and two Pis, hand copying gets confusing. Keep code and notes in an online repository and let every computer sync with it.
sudo apt install git  # once, on the Pi
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git clone https://github.com/YOU/REPO.git  # first time
git pull  # get the latest
git add . ; git commit -m "Describe the change" ; git push  # share
Signing in to GitHub: GitHub no longer accepts the account password for git push over HTTPS. Create a personal access token (or an SSH key for the Pi) and give the token when git asks for a password. Keep it private.
Not in git: large files (models of hundreds of MB, datasets, videos). Use a .gitignore and move them with scp or SFTP.

D. Connect from the laptop
15. Steps
  1. Install RealVNC Viewer (free) or another VNC viewer.
  2. Type the Pi's address in the address bar; accept the identity (fingerprint) message once.
  3. Sign in with the Pi user name and password (not an account of the VNC company). The desktop appears in a window.
viewer with a saved Pi
sign in with the Pi's account
the Pi desktop in a window (example on a Mac)
16. A comfortable desktop
  • Resolution: Preferences -> Screen Configuration (or Display Options in raspi-config).
  • Speed: on a slow network lower picture quality / colour depth in the viewer; remove the wallpaper.
  • Copy and paste usually works through the viewer.
  • Close it when finished: the desktop uses memory that models will need.
  • Never open VNC's port (5900) to the Internet.
Black or tiny desktop with no monitor? There is no real screen: in sudo raspi-config -> Display Options set a resolution (e.g. 1920x1080). The VNC server depends on the OS release (RealVNC Server on older ones; wayvnc possible with the Wayland desktop). If the viewer refuses or shows nothing, raspi-config -> Advanced Options lets me switch between Wayland and X11; X11 with RealVNC is the best-documented pair.

E. More than one network
17. A Pi can remember several Wi-Fi networks
  • Imager stored one network. Like a phone, a Pi can remember many and join whichever it finds, so the same Pi works at the lab and at home without re-writing the card.
  • Current Raspberry Pi OS uses NetworkManager, driven by nmcli.
nmcli connection show  # saved connections
nmcli device status  # devices; wlan0 = Wi-Fi
nmcli device wifi list  # networks in range now
# network in range now:
sudo nmcli device wifi connect "HomeWiFi" password "the-password"
# network NOT in range (prepare a saved profile):
sudo nmcli connection add type wifi con-name home ifname wlan0 ssid "HomeWiFi" \
   wifi-sec.key-mgmt wpa-psk wifi-sec.psk "the-password"
sudo nmcli connection modify home connection.autoconnect yes connection.autoconnect-priority 10
autoconnect-priority 10higher number = preferred when several are in range
sudo nmcli connection delete homeforget a profile
sudo nmtuimenu version: Edit a connection -> Add -> Wi-Fi
Do not cut my own branch: if I am connected over Wi-Fi and switch the Pi to another network, my SSH session ends. Add profiles first, test later, keep a monitor, keyboard or Ethernet cable as a way back.
Older OS (before Bookworm): Wi-Fi lives in /etc/wpa_supplicant/wpa_supplicant.conf (one network={ ssid="..." psk="..." } block each) or raspi-config's Wireless LAN. Check with cat /etc/os-release.

E. Finding the Pi; stable addresses
18. When .local does not work, find the IP
  • Router page (often 192.168.1.1 or 192.168.0.1): the list of connected devices shows the host name.
  • From Windows: ping raspi-lab.local shows the address if the name works; arp -a lists devices my laptop met recently. Raspberry Pi MAC addresses often start with b8-27-eb, dc-a6-32 or e4-5f-01 (newer boards use more).
  • With a screen: plug a monitor in and run hostname -I.
  • Then put the IP in the HostName line of my SSH config.
19. Keep the address stable
  • The router (DHCP) may give the Pi a new address after a reboot.
  • Best fix: a DHCP reservation (static lease): tell the router to always give this Pi's MAC address the same IP. Prefer this to a fixed address on the Pi: the router stays in charge of the numbers.
20. Two fallbacks
  • Phone hotspot: Pi and laptop on the phone's hotspot avoid guest and enterprise restrictions.
  • Ethernet cable straight between laptop and Pi: after about a minute both sides self-assign 169.254.x.x addresses and raspi-lab.local often works. Useful with no Wi-Fi at all.
Office and campus networks: many allow only registered devices or block device-to-device traffic. If the Pi will not join, ask the administrator about a guest / IoT network or registering the MAC address. Do not work around the rules.

F. Reaching a Pi in another network
21. Why it is hard
  • Laptop at home and Pi in the lab = two private networks. Each router hides its devices behind one public address and refuses unsolicited connections, and .local names never leave their network. Something must connect the two sides.

24. Example idea: a private network (Tailscale)
Create a free account; install the program on the laptop and sign in; install it on each Pi and sign in with the same account; then the devices reach each other by the names in the service's device list. Details change: read the vendor's current instructions.
# on the Pi (the vendor's installer; read the script first if you can)
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up  # prints a web address; open it and sign in
tailscale ip -4  # the Pi's private address, e.g. 100.x.y.z
Piping a script into the shell (curl ... | sh) runs downloaded code with my privileges: only for sources I trust, and never on a work computer without permission.
Policy first: installing remote-access software on a work laptop, or opening a path into a work network, can break the rules. Ask IT before trying Part F on any work device or network.
25. A sensible plan for two Pis and two laptops
  • Keep each Pi in one place and add the other place's Wi-Fi as a second profile, so I can also carry it.
  • Nickname every Pi in the SSH config on every laptop; use key login.
  • Code and notes in git; big files with scp.
  • For access from outside choose one approved method; do not combine several.

Instructor notes
35. A 60-minute lab
10 min the rough edges; demonstrate ssh lab versus the long form. 15 min students create the config file and a key. 15 min scp both ways and an SFTP program. 15 min VNC. 5 min where networks break.
  • Typical mistakes: config saved as config.txt; colon missing in scp; the private key copied instead of the public key; > instead of >> when adding a key (overwrites other keys); VNC with no resolution set.
  • Mini-assessment: ssh lab works without a password, and a screenshot of ls -l and the scp lines for a file copied both ways.
  • Policy: warn students not to install remote-access software on school or work computers without permission.
